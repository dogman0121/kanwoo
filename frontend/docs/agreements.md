# Соглашения по разработке фронтенда

Начни с [инструкций фронтенда](../AGENTS.md). Связи между маршрутами, провайдерами и клиентами API описаны в [архитектуре](architecture.md).

## Маршруты и компоненты

- Собирай маршрут и макет в `src/app/`. Предметные компоненты, формы и состояние размещай в соответствующем `src/features/<область>/`. Повторно используемые компоненты размещай в `src/components/`. Перед добавлением UI проверь существующие компоненты и тему Material UI.
- Используй строгий TypeScript и импорты через `@/`. Имена React-компонентов и их файлов пиши в `PascalCase`, имена хуков начинай с `use`. Сохраняй отступы соседнего кода.
- Оставляй загрузку, которой нужны `next/headers` или серверные переменные, на сервере. Объявляй `"use client"` на границе интерактивного поддерева, которому нужны состояние, эффекты, Redux или API браузера. Передавай через эту границу сериализуемые значения.

## Состояние

- Используй `useAppSelector`, `useAppDispatch` и `useAppStore` из `src/lib/state/hooks.ts`. Для нового состояния сначала проверь, есть ли подходящий slice и селектор в предметной области.
- Согласно [manifest.md](../manifest.md), самодостаточный компонент, который используется один раз, может получать данные через Redux; один компонент может читать несколько slices. Для общих компонентов с несколькими потребителями задавай явный интерфейс через props, если им достаточно входных данных и обработчиков.

## Изменения API

- Для запросов из серверного кода используй `serverFetch`, из браузера — `clientFetch`. Расширяй предметную обёртку в `src/lib/fetch/features/`, если она уже обслуживает нужный ресурс.
- При добавлении маршрута через `/api` проверь путь и метод в `src/lib/api/api-config.type.ts`, тип ответа и маршрут Flask. Для агрегированных ответов проверь поля по именам ресурсов и поведение при частичном отказе.
- При изменении мутации проверь авторизованный сценарий, передачу cookies и CSRF, ошибку API и обновление интерфейса. Для списков сохраняй используемый вид пагинации, а при отправке файлов следуй существующему шаблону с `FormData`.
- Передавай в `NEXT_PUBLIC_*` только значения, которые могут попасть в клиентский код. Серверные настройки и секреты держи в серверном окружении.

## Проверки

- Размещай `*.test.ts` и `*.test.tsx` в `src/__tests__/`. Для проверки поведения компонентов используй React Testing Library. Запускай `npm test` из `frontend/`, а для одной проверки передавай путь после `--`.
- Для правок общего компонента проверь один из реальных экранов, где он используется. При изменениях адаптивного интерфейса проверь мобильный и настольный варианты, если они есть. Для изменений App Router или серверной границы выполни `npm run build`.
