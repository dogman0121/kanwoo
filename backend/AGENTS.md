# Работа с бэкендом

## Структура и стиль

Приложение Flask находится в `kanwoo/`. Фабрика приложений — `kanwoo/create_app.py`. Само приложение в `manage.py` 

В предметных модулях, например `kanwoo/manga/`, ищите HTTP-маршруты в `routes.py` и обработчики в `handlers/`, схемы в `schemas.py`, бизнес-логику в `services.py`, а доступ к данным в `repositories.py`. Модели данных описаны в `models.py`. Вспомогательные сущности в `entities.py`. Возможные ошибки в `exceptions.py`.

Миграции SQL базы данных лежат в `migrations/versions/`, конфигурации Compose — в `docker/`.

Для инъекции зависимостей используется библиотека `dependency-injector`. Для маршализации и валидации данных используется библиотека `marshmallow`. Для работой с SQL базами данных `SQLAlchemy`.

Используйте четыре пробела для отступов и `snake_case` для имён функций и модулей. При добавлении маршрута следуйте структуре соседних маршрутов и схем.

Перед изменением кода сверяйся с [архитектурой бэкенда](docs/architecture.md) и [соглашениями по разработке](docs/agreements.md).

## Скрипты Poetry

Запускайте команды из каталога `backend` после установки зависимостей через `poetry install`. Для `dev`, `test` и `db_migrate` нужен запущенный Docker с Docker Compose.

| Команда | Что делает |
| --- | --- |
| `poetry run dev` | Поднимает сервисы из `docker/docker-compose.dev.yml`, применяет миграции, загружает начальные данные и запускает Flask на порту `5000`, Celery Worker и Celery Beat. При завершении останавливает процессы и сервисы Compose. |
| `poetry run test` | Поднимает сервисы из `docker/docker-compose.test.yml`, запускает `pytest` и останавливает сервисы после прогона. |
| `poetry run db_migrate -m "Описание миграции"` | Поднимает сервисы разработки, вызывает `flask db upgrade` для применения существующих миграций и генерирует новую через `flask db migrate`. Аргумент `-m` обязателен. |
| `poetry run db_upgrade` | Заглушка, которая выводит `db_upgrade`. Для применения миграций к настроенной и доступной базе используйте `poetry run flask db upgrade`. |

## Локальный запуск и миграции

Выполняйте команды из `backend/` с Python 3.13, Poetry и Docker Compose.

- `poetry install` устанавливает зависимости.
- `poetry run dev` запускает локальные зависимости, применяет миграции, загружает начальные данные и поднимает Flask на порту 5000.
- `poetry run db_migrate -m "описание изменения"` создаёт миграцию. Проверьте сгенерированный файл перед коммитом. При запущенной локальной базе для применения миграций вручную используйте `poetry run flask db_upgrade`.

## Тестирование

Команда `poetry run test` запускает тестовые сервисы через Docker Compose и выполняет pytest. Проверяйте сводку pytest в выводе, поскольку обёртка не передаёт его код завершения. Размещайте файлы `test_*.py` в `tests/unit/`, `tests/integration/` или `tests/end2end/` в зависимости от уровня проверки.
