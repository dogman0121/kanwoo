# Руководство по работе с репозиторием

## Инструкции по проектам

Эти правила распространяются на ВЕСЬ репозиторий. Перед изменениями в сервисе прочитайте его инструкции. Если задача затрагивает оба сервиса, прочитайте оба файла.

- [Бэкенд Flask](backend/AGENTS.md)
- [Фронтенд Next.js](frontend/AGENTS.md)

Для совместного локального запуска выполните `bash dev.sh` из корня после настройки обоих сервисов. Параметры `--mode=backend` и `--mode=frontend` запускают один сервис.

## Как принимать решения

1. Определи ожидаемое поведение и критерий проверки. Для исправления ошибки проследи путь от точки входа до места, где поведение расходится с ожидаемым.
2. Изучи ближайший код, его вызовы и тесты. Переиспользуй принятые в проекте решения, если они подходят задаче.
3. При неоднозначности сделай обратимое действие и укажите его в итоге. Уточни требования заранее, если решение меняет публичный контракт, затрагивает сохранённые данные или требует необратимых действий.

## Как вносить изменения

1. Перед изменением сформируй ПОШАГОВЫЙ план и спроси разрешения. После чего
создай отдельную ветку, сделай switch и примени изменения там.
2. Изменения должны поисходить в рамках задачи и сохранять существующие пользовательские изменения. Для изменений на стыке сервисов проверь обе стороны API, включая форматы данных и обработку ошибок.
3. Локальные секреты хранятся вне Git. Переменные окружения хранятся в .env во время локальной разработки, а в production передаются через CI CD в docker контейнер.
4. Если при тестировании встречается ошибка, необходимо написать тест, который проверяет поведение функции.

## Как проверять результат

Начни с проверки изменённого поведения по инструкциям сервиса. Для сквозных изменений проверь сценарий через его обычную точку входа. Добавь регрессионный тест, если существующие проверки не обнаружат повторение ошибки. После завершения работы повторно запусти тесты для затронутых частей проекта. В итоговом сообщении перечисли команды, сообщи, какие тесты прошли и какие завершились ошибкой. Если тесты запустить не удалось, укажи причину и что осталось непроверенным.

## Коммиты и пул-реквесты

Пиши короткие заголовки коммитов в повелительной форме, например `Add Bash development launcher`. В пул-реквесте опиши изменение и способ проверки, приложи ссылки на связанные задачи. Отметь миграции и изменения конфигурации, а для видимых изменений интерфейса приложи скриншоты.
